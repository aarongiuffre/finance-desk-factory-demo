# Staged sudo steps (for Aaron)

Agents on this box run without sudo. Anything that needs root is staged here as a
script that does a dry run by default and changes nothing until it gets `--apply`.

**No validation or holdout grant counts until `leave_root_equivalent_groups.sh --apply` has run** (fold_gate refuses them while it detects slowglow in docker or wheel). That refusal is only a tripwire, not a lock: a root-equivalent user can hide its membership (docker --user with its own /etc/group, a renamed group). **Any validation or holdout grant made before step 5 is invalid and must be thrown out**, with its results. The real lock is encryption with Aaron's key plus the off-box witness. Backlog (M3'' marker): step 5 `--apply` writes a root-owned marker with the gate-log head seq; gated grants then require a seq above it.

| Script | What it does | Run |
|---|---|---|
| `install_finance_health_system_onfailure.sh` | Adds `OnFailure=finance-health-onfailure@%n.service` drop-ins to the system units finance-quote, finance-refresh, finance-facts and zfs-replicate, plus a system template that runs `scripts/finance_health.py` as slowglow. Nothing is restarted. | `sudo bash ops/staged_sudo/install_finance_health_system_onfailure.sh` (dry run), then `--apply`; `--revert` (dry run) then `--revert --apply` undoes it |
| `install_gate_key.sh` | Pins Aaron's public SSH key in root-owned `/etc/finance-gate/allowed_signers` (namespaces finance-holdout, finance-custody, finance-go). It is the only key fold_gate and encrypt_full_period trust; the repo copy is ignored (Verifier F6). v6: ssh-ed25519 only; prints the SHA256 fingerprint to commit as REGISTRY.yaml `gate.signer_fpr` and prereg `gate_signer_fpr` (M3: while slowglow is in docker/wheel only that key counts); refuses any key slowglow holds in ~/.ssh or its ssh-agent (S11). | `sudo bash ops/staged_sudo/install_gate_key.sh aaron.pub` (dry run), then `--apply`; `--revert [--apply]` moves the pin aside |
| `leave_root_equivalent_groups.sh` | Removes slowglow from `docker` and `wheel`, which are root-equivalent. Every other on-box lock depends on this step. **Hard prerequisite for any validation or holdout read (Verifier v7 M3'):** the docker/wheel refusal while slowglow is in either group is a tripwire, not a lock (membership can be hidden); any validation or holdout grant made before this step is invalid; discard it and its results. (Dev still works on the committed fingerprint.) If Engineering keeps these groups (GLM, Media, Hermes tooling), gated evaluations must run off-box instead - see the design note in ops/edge_threat_model.md. | dry run, then `--apply`; `--revert [--apply]` |
| `install_finance_gate_user.sh` | Optional. Moves the two chained logs and their anchors to `/var/lib/finance-gate`, owned by the `finance-gate` user, and adds an append-only sudo helper (Verifier F3/F12). Root-side work goes through `finance_gate_migrate.py` (sha-pinned in the script): no symlink following, ownership checks, copies under the chain flocks, idempotent with no anchor rollback (Verifier v4). v5: chainlog.py and finpaths.py are sha256-pinned too (re-pin when they change); a failed verify-chain removes the sudoers rule as well as the marker; revert reads `/var/lib/finance-gate` through the helper's `read-file`. | dry run (works without sudo), then `--apply`; `--revert [--apply]` |
| `split_research_dataset.sh` | Verifier v5 C-E2, reworked v6. Moves the 2020+ research data (raw/price/h1_universe, folds/validation, raw/dera_*/202[0-6]q*.zip -> raw/research_zips/) onto `fastpool/finance-research/*` with `com.sun:auto-snapshot=false` and `finance:replicate=false`. Step 1 `--patch-replicate --apply` patches the sha-pinned `/usr/local/bin/zfs-replicate.sh` to skip such datasets (backup kept); the split refuses until then. Step 2 `--apply` is resumable and idempotent (root-only state file `/var/lib/finance-research-split/state`): per item create at a staging mount, copy, verify (sha256 plus type/owner/group/mode), swap into place (original renamed `.presplit`, re-verified), remove the original. It refuses while any process holds an in-scope file open (fuser, else lsof). `--status`, `--list-snapshots` (every fastpool/backuppool ROOT snapshot that may hold the data). **The holdout is not locked by this step**: the pre-split snapshots keep the plaintext until `destroy_research_snapshots.sh` runs. After the split, a validation copy can no longer be rebuilt by hard links (other dataset); restore it from the archive. | `--patch-replicate` (dry run) then `--patch-replicate --apply`; dry run, then `--apply` (re-run after any failure); `--revert [--apply]` works from the state file; `--patch-replicate --revert --apply` restores the replicate script |
| `destroy_research_snapshots.sh` | Verifier v6 C-E2, opt-in. Destroys exactly the snapshots `split_research_dataset.sh --list-snapshots` names (fastpool/ROOT/cachyos and its backuppool replica, from the oldest in-scope file until the split completed). Refuses unless the split is complete and a post-split snapshot exists on both pools (so incremental replication keeps a common base). Destroys OS rollback points from before the split; no undo. Only after it (and encrypt `--remove-originals`) is the holdout locked against snapshot reads. | dry run (lists exactly what it destroys), then `--apply --i-understand-backups` |

See `ops/edge_threat_model.md` for the order and for what each step closes.
